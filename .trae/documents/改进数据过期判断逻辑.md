# 改进数据过期判断逻辑

## 问题分析

当前的过期判断逻辑仅基于文件修改时间(`st_mtime`)，存在以下问题：

* 文件时间可能被其他操作影响（如复制、备份）

* 文件时间较新但实际数据内容可能过时

* 不同类型数据的过期标准不同

## 改进方案

### 1. 基于数据内容的过期判断

对于历史数据，检查数据的最后一个时间索引，与当前日期比较：

* 提取DataFrame的最后一个时间索引

* 计算与当前日期的差值

* 如果差值超过设定的阈值，则判断为过期

### 2. 支持不同数据类型的定制化判断

* **历史数据**：检查最后一个数据点的时间

* **实时数据/快照**：严格基于文件时间

* **因子数据**：根据因子更新频率判断

### 3. 混合判断策略

结合文件时间和数据内容进行判断，提高准确性：

1. 首先检查文件时间，快速过滤明显过期的文件
2. 对于文件时间较新的文件，进一步检查数据内容
3. 只有两者都通过时，才认为数据有效

## 实现步骤

### 步骤1：修改`load_data`方法

* 添加基于数据内容的过期判断逻辑

* 支持不同数据类型的定制化判断

* 保持向后兼容性

### 步骤2：添加辅助方法

* `_check_data_expiry`：统一处理数据过期判断

* `_get_data_end_date`：提取数据的最后一个时间索引

### 步骤3：更新方法参数

* 添加`expiry_check_method`参数，允许用户选择判断方式

* 支持基于数据天数的过期阈值

## 代码实现示例

```python
# 改进后的过期判断逻辑
def _check_data_expiry(self, data: pd.DataFrame, file_path: Path, update_if_expired: bool, max_age_hours: int, data_type: str) -> bool:
    """检查数据是否过期"""
    if not update_if_expired:
        return False
    
    # 1. 快速检查：文件时间
    file_age = datetime.now() - datetime.fromtimestamp(file_path.stat().st_mtime)
    if file_age > timedelta(hours=max_age_hours):
        logger.info(f"文件已过期 ({file_age}), 需要更新: {file_path}")
        return True
    
    # 2. 深度检查：数据内容
    try:
        if data_type.startswith('historical'):
            # 历史数据：检查最后一个数据点的时间
            last_data_date = data.index.get_level_values('time_key')[-1] if 'time_key' in data.index.names else data.index[-1]
            data_age = datetime.now() - last_data_date
            # 根据数据周期调整过期阈值
            if data_age > timedelta(days=7):  # 示例：历史数据超过7天未更新则过期
                logger.info(f"数据内容已过期 ({data_age}), 需要更新: {file_path}")
                return True
    except Exception as e:
        logger.warning(f"检查数据内容过期时出错: {e}")
    
    return False
```

* 需要处理不同数据格式的兼容性问题
